# PLAN-186 — Configured objective direction check with existing validation

SC-04/10 permit the least costly adequate constraint check instead of another
model. Before adding a reviewer route, exercise an existing supported objective
profile: a decision artifact proposes a provider, while a configured required
compliance command checks an explicit local-only constraint before that decision
is accepted. No production change, helper, ledger, new model call or network use.

The fixture supplies original wording and a structured constraint as its declared
authorized interpretation. A structurally valid/confident remote proposal passes
the real JSON structural check but fails the separate required compliance check;
no accepted output/commit skip is published. Repairing only the candidate to local
passes both checks and uses existing receipt/Git-skip acceptance. A local proposal
is a valid control without inventing extra features or objections. An unavailable
required check is explicitly blocked and cannot become success. Preserve the
actual configured policy, source bytes, result identity and limitation evidence.

Also mutate accepted candidate bytes and then the constraint source: old receipt
reuse fails and changed validation-input basis blocks revalidation before commands.
The configured trigger/check is explicit in the manifest, independent of the
candidate's confidence or structural success. This is task-level acceptance of a
decision artifact, NOT proof of automatic risk detection or a provider-dispatch
preflight, and not prevention of arbitrary effects before validation.

Scope is one local deterministic process profile. The fixture does not derive
constraints semantically from prose, prove model judgment/quality/local inference,
execute a cloud provider, implement selected-review author assessment or close full
SC-04/10/P5. Do not upgrade aggregate coverage. Run focused fixture, build, full
unit/mock/conformance gate, own review and independent exact-head review before merge.
